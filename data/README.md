> **SYNTHETIC — software-test data, not field evidence.** Every file in `data/`
> is generated by a seeded script (see `ml-service/training/make_fixture.py`).
> It exists so the ML pipeline, API, and tests can run end-to-end without real
> agricultural data. Nothing here is a real outbreak record, real price, or
> validated recommendation.

## Contents

```
data/
└── processed/
    └── crop-disease-fixture.csv   # 6,080 rows × 22 columns (seeded, deterministic)
```

## Fixture schema (`crop-disease-fixture.csv`)

| Column group | Columns | Values |
|---|---|---|
| `crop` | 1 | `tomato`, `maize`, `wheat`, `potato`, `rice`, `cotton` |
| `symptom_<id>` | 14 | `0` / `1` (see symptom catalogue below) |
| `env_<field>` | 6 | see environment catalogue below |
| `target` | 1 | condition id (see class list below) |

The serving and training layers share this schema via
`ml-service/app/features.py::FEATURE_COLUMNS`, so a dataset you drop in with the
same columns trains a wire-compatible artifact.

### Symptom ids (14, the closed vocabulary)

`leaf-brown-spots`, `leaf-yellowing`, `leaf-powdery`, `leaf-rust`,
`leaf-watersoaked`, `leaf-curl`, `leaf-tip-burn`, `plant-wilting`,
`plant-stunted`, `plant-lesion-stem`, `plant-lodging`, `fruit-rot`,
`fruit-spots`, `ear-smut`

Source of truth: `ml-service/app/schemas.py::SYMPTOM_IDS`. The API rejects
(`422`) any request with ids outside this list.

### Environment fields (6)

| Field | Allowed values |
|---|---|
| `humidity` | `high`, `normal`, `low` |
| `recentRainfall` | `heavy`, `moderate`, `low` |
| `temperatureBand` | `15-25`, `26-32`, `above-32` |
| `soilMoisture` | `wet`, `medium`, `dry` |
| `drainage` | `poor`, `adequate` |
| `growthStage` | `seedling`, `vegetative`, `flowering`, `fruiting` |

Unknown or missing values are encoded as `unknown` — the model sees that as its
own category rather than silently filling in a guess.

### Target classes (9)

`healthy`, `tomato-early-blight`, `tomato-powdery-mildew`, `maize-nclb`,
`wheat-stripe-rust`, `potato-late-blight`, `rice-leaf-yellowing`,
`cotton-mixed-stress`, `generic-stress`

Names describe fixture-like *patterns* (e.g. "Early blight-like pattern"); they
are deliberately hedged because they are labels on synthetic data, not
laboratory-verified diagnoses.

## Regenerating the fixture

Deterministic (seeded) — run twice, get identical bytes:

```powershell
cd ml-service
.venv\Scripts\python.exe -m training.make_fixture
```

## Replacing the fixture with real data

1. Curate a dataset with exactly the columns above (you may extend the symptom
   vocabulary, but then update `SYMPTOM_IDS`, `LABELED sets in the frontend, and
   retrain).
2. Save it as `data/processed/<your-name>.csv` (keep a `target` column with a
   class id from `LABEL_MAP` in `ml-service/app/features.py`).
3. Retrain and the artifact metadata will record which dataset it came from:

```powershell
cd ml-service
.venv\Scripts\python.exe -m training.train
# optional explicit path:
#   .venv\Scripts\python.exe -c "from training.train import train; train(...)"
```

When the file name does not contain `fixture`, metadata `dataset.nature`
switches to "user-provided dataset" and the operationNature wording changes —
the system always names what it was actually trained on. Until real curated
data replaces this fixture, **every probability and metric in this project
describes the fixture distribution, not field performance.**
